# Genie Code: Clinical Study Hub deploy instructions

You are helping a user deploy this demo after they cloned the repo as a **Databricks Git Folder**.
All data is synthetic. Do not introduce real customer or patient data.

## Goal

Deploy two Declarative Automation Bundles (DABs) and wire one-time resources so the Study Hub works end to end:

1. **Root bundle** (`databricks.yml`): UC schema and volumes, Lakeflow Declarative Pipelines, onboarding job, notebooks.
2. **App bundle** (`app/study-hub/databricks.yml`): Databricks App (portfolio, onboard, approvals, insights, Genie).

Prefer the guided path: open and run `00_install.py` (Run All). If the user asks you to deploy yourself, collect the missing inputs first, then run the same steps the install notebook performs.

## Always ask before deploying (if missing or unclear)

Ask one question at a time when possible:

| Input | Default | Notes |
|-------|---------|-------|
| SQL warehouse ID | (none) | **Required.** Serverless or Pro warehouse the user can use. |
| Catalog | `clinical_demo` | Created or used for demo tables and volumes |
| Schema | `study_onboarding` | Under that catalog |
| LLM endpoint | `databricks-claude-sonnet-4-5` | For AI study insights (`ai_query`) |
| Create Lakebase project? | yes | Holds approval state and the portfolio synced table |
| Create Genie space? | yes | Needed for Ask Genie in the app |
| Deploy the app? | yes | Study Hub UI |

Do **not** invent a warehouse ID. If the user does not know it, help them find it (SQL warehouses list or settings) or list warehouses with the CLI or SDK.

## Deploy sequence (do in order)

From the **repo root** of the Git Folder (the directory that contains `databricks.yml` and `00_install.py`):

1. Confirm the Git Folder root and `cd` there.
2. Collect the inputs above.
3. **Preferred:** open `00_install.py`, set the widgets, **Run All**.
   **Or** run the equivalent CLI steps:

```bash
# Follow 00_install.py in this order (do not skip the seed jobs):
# 1) platform bundle deploy
# 2) upload data/samples/*.zip to /Volumes/<CATALOG>/<SCHEMA>/samples/
# 3) run the onboarding job for ONC-101 and CARD-202 (leave RESP-303 unpublished)
#    (this also builds study_portfolio via the publish_portfolio task)
# 4) Lakebase project, then the Lakebase catalog and the portfolio synced table
# 5) Genie space (after Gold tables exist)
# 6) app bundle with --var sql_warehouse_id, files_id, job_id, postgres_*, genie_space_id
#    Two passes: deploy (creates the app and its service principal), then grant that principal
#    read access to the Gold schema (UC) and the serving schema (Lakebase), then deploy again to build.
#    The notebook fails unless the active app deployment reports SUCCEEDED.

databricks bundle deploy -t dev \
  --var="catalog=<CATALOG>" --var="schema=<SCHEMA>" \
  --var="warehouse_id=<WAREHOUSE_ID>" --var="llm_endpoint=<LLM_ENDPOINT>"

cd app/study-hub
databricks bundle deploy \
  --var="sql_warehouse_id=<WAREHOUSE_ID>" \
  --var="files_id=<CATALOG>.<SCHEMA>.landing" \
  --var="job_id=<JOB_ID>" \
  --var="genie_space_id=<GENIE_SPACE_ID>"
databricks bundle run app
```

4. Tell the user the **App URL**, the catalog and schema, the job name, the Lakebase synced table, and the Genie space name.
5. Demo tip: warm the SQL warehouse, then open the app and use `demo_assets/RESP-303_study_package.zip` for a live onboarding run (or `demo_assets/DERM-404_study_package.zip` if RESP-303 is already published). After it publishes, open the study's **Quarantine** tab to show coverage, reconciliation and the review flow.
6. Optional checks: `scripts/verify_dq.sql` (every row `failures = 0`) and `scripts/genie_eval.py` (no quarantined subject in Genie answers).

Upgrading an install that predates quarantine-first data quality: the `study_portfolio` table gains coverage columns, so delete the Lakebase synced table (`databricks postgres delete-synced-table synced_tables/study_hub_lakebase.serving.study_portfolio`) and re-run `00_install.py`, which recreates it and re-applies the `serving` grants. Until then the portfolio page falls back to the SQL warehouse.

## Hard rules

- Never commit or print secrets or personal access tokens.
- Never write real tokens into `.env` files that could reach git.
- Keep the synthetic-data framing. This is demo data only.
- Say **Lakeflow Declarative Pipelines** (not "medallion pipeline") in user-facing text.
- If deploy fails on permissions (create catalog, volumes, jobs, apps, Lakebase, Genie), explain the missing privilege and stop.

## Repo map

- `databricks.yml` + `resources/` + `src/`: platform DAB (Lakeflow Declarative Pipelines, notebooks, job)
- `app/study-hub/`: Study Hub app DAB (AppKit, React, Express)
- `00_install.py`: one-click install notebook
- `data/samples/`, `demo_assets/`: synthetic study packages (generated by `src/data_gen/generate_studies.py`)
- `docs/`: decisions, value model, AI workflow
